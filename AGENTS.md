# Working in this repository

Read README.md, docs/PROJECT-BRIEF.md, and docs/STATE.md first. Consult docs/EVIDENCE.md and historical material when relevant; do not load the predecessor repositories wholesale.

This is a fresh product, currently in architecture planning. The user has authorized repository setup and preparation for planning. Substantial implementation, remote publication, and changes to predecessor repositories are outside the current setup task.

- Use research and engineering reasoning first. Compare materially different approaches and seek evidence against the preferred one. Do not default to either a minimal skill or a custom decision engine.
- Treat selectable reasoning modes and a shared adaptive loop as hypotheses. Do not require every task to traverse every mode or assign an agent to each responsibility.
- Preserve the user's outcome, constraints, and decisions. Keep agent interpretations and proposals distinguishable from confirmed user intent.
- Prefer host-native authentication, billing, model selection, permissions, and execution capabilities. Verify current host behavior from official documentation or source before relying on it.
- Do useful work autonomously within the current phase. Ask about consequential unresolved product choices when necessary; avoid repeated approval for routine reversible work.
- An experiment should resolve a consequential uncertainty and have a result that could change a decision. Small behavioral samples and reviewer agreement do not establish broad benefit.
- Verify deterministic behavior appropriate to changes. Avoid testing rituals and unsupported reliability or efficiency claims.
- Keep instructions and state concise. Record material decisions and their evidence, not every action or incident. Do not grow a rule for every failure.
- Inspect Git status before editing and preserve unrelated work. Do not archive, modify, copy wholesale, or merge the predecessor repositories as part of planning.

Report the outcome, evidence, uncertainty, and next useful decision in plain language. Repo guidance is for contributors; it is not automatically product prompt content.
